# Eloquent Query Plan Analysis

Eloquent provides several methods for analyzing and optimizing query plans, including `get:query-plan`. This command allows you to inspect the query plan generated by Eloquent's query builder.

### Eager Loading

When using eager loading, Eloquent will fetch related models along with the main model. By default, Eloquent uses lazy loading, which means that related models are loaded on demand. However, this can lead to poor performance and unnecessary database queries.

To enable eager loading, use the `--eager-load` option when running `get:query-plan`. For example:
```bash
php artisan get:query-plan --model=User --relation=orders --eager-load=true
```
This will fetch all orders for the user with ID 1 along with the user model.

### Lazy Loading

When using lazy loading, Eloquent only loads related models when they are actually needed. This can be beneficial in reducing database queries and improving performance.

To enable lazy loading, simply omit the `--eager-load` option when running `get:query-plan`. For example:
```bash
php artisan get:query-plan --model=User --relation=orders
```
This will only load the user model, without any related orders.

### Join Types

When using eager loading with joins, you can specify the join type using the `--join-type` option. The three supported join types are:

*   `inner`: This is the default join type. It returns a subset of rows from both tables where there is a match.
*   `left`: This returns all rows from the left table and matching rows from the right table.
*   `right`: This returns all rows from the right table and matching rows from the left table.

For example, to use an inner join when running `get:query-plan`, you can specify:
```bash
php artisan get:query-plan --model=User --relation=orders --join-type=inner
```
This will return a subset of rows from both tables where there is a match.
